# Security Policy

## Supported versions

Open Flow is currently pre-release. Security fixes are applied to the default branch.

## Report privately

Do not open a public issue for:

- Exposed personal information
- Unredacted screenshots
- Passwords, API keys, access tokens, session data, or private links
- Authentication or authorization weaknesses
- Vulnerabilities that could expose user submissions or accounts
- Instructions or proof-of-concept material that would make exploitation easier

Use GitHub's private vulnerability reporting feature when it is enabled. If it is not available, contact the maintainer through the private contact method listed on the repository profile. Do not attach sensitive files to a public issue.

## Include

- A short description of the problem
- The affected file, page, feature, or commit
- Safe reproduction steps when relevant
- The possible impact
- Suggested mitigation if known

Do not access data that is not yours, disrupt the service, or test against other users.

## Response goals

Maintainers should acknowledge a valid report, limit exposure, remove sensitive content when necessary, and publish a fix or notice when it is safe to do so. Timelines depend on severity and project capacity.
